# Windows 11: проверка portable HR Matcher

## Что программа делает автономно

Программа сопоставляет Excel-реестр и файлы резюме по имени файла. Содержимое PDF/DOC/DOCX не читается, AI не используется, интернет не нужен.

Основные правила:

- поддерживаются ФИО из двух и трех частей: `Фамилия Имя`, `Фамилия Имя Отчество`;
- допускается отсутствие отчества в имени файла;
- поддерживается обратный порядок: `Имя Фамилия`;
- поддерживается кириллица и латиница: `Громов Сергей` -> `Siarhei Hromau`;
- поддерживаются лишние слова в имени файла: `CV`, `resume`, `engineer`, `final`, расширения файлов;
- поддерживаются лишние пробелы, дефисы, подчеркивания и точки;
- поддерживается слитное имя файла без пробелов, если в нем видны минимум два признака ФИО: например `IvanovIvan.pdf`;
- совпадение по одному имени без фамилии не считается надежным.

## Важное правило для резюме

Если резюме не закреплено автоматически, оно не пропадает. В отчете есть листы:

- `Проверка резюме` - каждый файл резюме, лучший кандидат, score и причина;
- `Лишние резюме` - файлы, которые не были автоматически закреплены за строкой Excel.

Так как в реальном процессе каждое резюме должно быть в Excel, лист `Лишние резюме` нужно воспринимать не как "мусор", а как список для обязательной ручной проверки: файл есть, но алгоритму не хватило надежных признаков.

## Объем 3000+ файлов

Matching больше не делает полный перебор `3000 x 3000`. Сначала строится быстрый индекс по ФИО и транслитерации, затем точное сравнение выполняется только по вероятным кандидатам.

Проверочный синтетический прогон:

```text
3000 кандидатов
3000 файлов резюме
3000 найдено
время matcher: около 0.67 сек на MacBook
```

На Windows фактическое время будет зависеть в основном от копирования файлов и скорости диска. Для 3000 PDF нормальна обработка в пределах минут, особенно если файлы лежат на сетевом диске или в OneDrive.

## Что чаще всего ломается на разных Windows-компьютерах

1. **Windows Defender / SmartScreen**
   - Неподписанный `.exe` может показать предупреждение.
   - Решение: `More info` -> `Run anyway`, либо добавить доверенную папку.

2. **Запуск из архива**
   - Нельзя запускать прямо из `.zip`.
   - Сначала распаковать всю папку `HRMatcherPortable`.

3. **Нет прав на запись**
   - Папка результата должна быть доступна на запись.
   - Лучше выбирать обычную локальную папку: `Documents\HRMatcherResult`.

4. **Excel-отчет открыт**
   - Если `resume_match_report.xlsx` открыт в Excel, повторная запись может не пройти.
   - Закрыть отчет и запустить снова.

5. **Сетевые диски / OneDrive**
   - Работает, но медленнее и иногда дает блокировки файлов.
   - Для массового запуска лучше скопировать Excel и резюме на локальный диск.

6. **Очень длинные пути**
   - Windows может упираться в лимит длины пути.
   - Лучше держать проект ближе к корню: `C:\HRMatcher\`.

7. **Кириллица в путях**
   - Программа поддерживает кириллицу.
   - Если на конкретном компьютере проблема с путями, сначала проверить на простой папке без спецсимволов: `C:\HRTest\`.

## Где может помочь DeepSeek

DeepSeek или другой AI можно добавить только как дополнительный слой для ручной проверки, но не как основу.

Безопасный вариант:

- AI выключен по умолчанию;
- AI вызывается только для строк из `Лишние резюме` или `Проверка резюме`;
- в AI отправляется не сам PDF, а только имя файла резюме и 5-10 лучших кандидатов из Excel;
- AI возвращает рекомендацию, но не закрепляет файл автоматически;
- итоговое решение все равно остается в отчете как `на проверку`.

Для текущей задачи AI не обязателен. Компьютер может выполнить matching сам, если в имени файла есть фамилия/имя или их транслитерация.

## Ответ на главный вопрос

Да, компьютер может сделать это без искусственного интеллекта.

AI нужен только для совсем плохих случаев: файл назван `resume.pdf`, `cv_final.pdf`, `document_123.pdf`, или ФИО в имени файла вообще отсутствует. Если в имени файла есть хотя бы фамилия и имя, автономный алгоритм надежнее, дешевле, быстрее и не требует интернета.
